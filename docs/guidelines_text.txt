Mini-Project Assignment 
Guidelines and Instructions 
This document outlines the structure, deliverables, and evaluation criteria for the upcoming 
mini-project. Please read all instructions carefully. 
1. Overview & Timeline 
This is a one-week mini-project designed to give you hands-on experience in solving a 
problem within a team. 
 Project Start Date: Tuesday, September 29, 2026 
 Project Duration: 1 Week 
 Review & Demonstration Dates: Monday October 05  to Friday, October 09, 2026 
 Deliverables Submission Deadline: Saturday October 10 2026 (11:59 PM) 
2. Team Formation & Problem Statement 
 Team Composition: You have been randomly assigned to teams of two members 
within your respective sections. The team list will be circulated separately. 
 Problem Assignment: Each team has been randomly assigned a numbered problem 
statement. Please refer to the master list to find the problem statement corresponding 
to your team's assigned serial number. 
3. Project Deliverables 
Each team is required to submit the following items for evaluation. All items are 
mandatory. 
A. Source Code in a GitHub Repository 
 All code developed for the project must be hosted in a private GitHub repository. 
 The repository must be shared with the faculty (and your assigned Teaching 
Assistants (TAs) if any) 
 The repository should include a README file with instructions on how to set up 
and run your project. 
B. One-Page Write-up 
 A concise, two-page summary of your project. 
 The write-up should include: 
o Your problem statement 
o The dataset details 
o The approach you took to solve it 
o A brief overview of your implementation 
=== PAGE 2 ===
o Conclusions  
 The document must be submitted in PDF format. 
4. Final Review & Demonstration 
 A mandatory review session will be held for all teams. A detailed schedule will be 
shared by the faculty. 
 During the review, each team must present their work using a presentation (slide 
deck) and give a live demonstration of the working code. 
 Be prepared to explain your methodology, code structure, and answer questions from 
the evaluation panel. 
5. Evaluation and Marks 
 This mini-project carries a total of 10 marks. 
 The final grade will be based on: 
o Quality of deliverables 
o Code functionality 
o Repository maintenance 
o Clarity of the write-up 
o Presentation 
o Live demonstration 
o Performance during the Q&A session 
o Individual Contribution 
For any questions or clarifications, please contact the faculty. 
Good luck!
